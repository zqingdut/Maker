# Still Gallery

一个**零依赖**的图片 + 提示词画廊：把生图结果和它们对应的提示词关联起来，公开浏览，
再配一个受保护的管理后台用于导入、筛选、批量整理和直接生图。

- **公开画廊** `GET /` —— 自由瀑布流照片墙。**主界面不显示提示词**，点击任意一张进入详情页才展示完整提示词。
- **管理后台** `GET /admin` —— 单管理员账户，8 个标签页：AI 生成 / 生成记录 / 导入图片 / 日志导入 / 已入库作品 / 生成指标 / 运行日志 / 数据导出。
  标签名**从 DOM 读**，不在 JS 里另存一份：写死的副本一旦和 HTML 走散，多出来的那个标签点下去
  会被静默回落成「AI 生成」，表现就是「点了没反应」。
- **排队生图**：点「开始生成」直接入队，默认同时跑 8 个（可在后台调 1–32），超出的排队；耗时样本按模型汇总，可查每个模型的平均出图时间。
- **提示词记录**：输入框右边记着最近 10 条提交过的提示词（先进先出），点一条就填回去；
  只存在这台浏览器的 `localStorage` 里，不进服务端。
- **无 npm 依赖**：只用 Node 内置模块（`node:http`、`node:crypto`、`node:fs`），
  `git clone` 之后不需要 `npm install`，没有构建步骤。

---

## 环境要求

- **Node.js >= 20**（`package.json` 的 `engines` 字段；本项目在 Node 22 上开发和验证）。
- 不需要数据库，不需要 Docker，不需要任何第三方包。

## 快速开始

```bash
cd outputs/still-gallery

# 直接启动（默认 http://127.0.0.1:4317）
npm start
# 等价于
node server.mjs
```

启动后终端会打印三个地址：

```
Still Gallery 已启动 → http://127.0.0.1:4317
画廊首页: http://127.0.0.1:4317/
管理后台: http://127.0.0.1:4317/admin
```

### 第一次使用

1. **首次启动会自动播种示例数据。** 如果 `data/images.json` **不存在**，服务会把
   `data/demo.json` 的内容写进去（这是刻意保留在版本控制里的种子数据）。
   想从**空库**开始，请把 `data/images.json` 的内容写成 `[]` 再启动——
   **直接删掉它只会重新播种一遍示例数据**（播种条件是「文件不存在」）。
   播种只发生在启动时，之后不会覆盖你已有的数据。
2. **打开 `/admin` 设置管理密码。** 此时还没有管理员账户，页面会引导你「初始化」。
   密码**至少 10 个字符**（`/api/auth/setup` 会校验）。
   密码以 **scrypt 加盐哈希**（N=16384, r=8, p=1, keylen=64）写入 `data/auth.json`，
   **不保存明文**。
3. 之后每次进后台用这个密码登录即可。

### 后台端口 / 监听地址

默认监听 `127.0.0.1:4317`，即**只有本机可访问**。要让局域网内的其它设备访问，
显式指定 `HOST`（注意：服务本身没有 TLS，也没有多用户体系，暴露到公网前请自行加反向代理和 HTTPS）：

```bash
HOST=0.0.0.0 PORT=8080 node server.mjs
```

### 常驻运行 / 开机自启

`scripts/service/` 下有一套服务脚本，Linux 走 **systemd**、macOS 走 **launchd**，
安装脚本自动识别平台。**一个命令装好，之后开机（或登录）自动起。**

```bash
cd outputs/still-gallery

./scripts/service/install-service.sh              # 安装并立即尝试启动
./scripts/service/service.sh status               # 看状态 + HTTP 探测
./scripts/service/service.sh logs                 # 跟日志
./scripts/service/service.sh restart              # 重启

./scripts/service/install-service.sh --uninstall  # 卸载（保留数据）
```

| | Linux | macOS |
|---|---|---|
| 默认模式 | `--system`（systemd system unit，需 sudo） | `--user`（LaunchAgent，免 sudo） |
| 开机自启 | `systemctl enable` | `RunAtLoad` |
| 用户模式 | `--user` → `~/.config/systemd/user/` | `--user` → `~/Library/LaunchAgents/` |
| 系统模式 | `--system` → `/etc/systemd/system/` | `--system` → `/Library/LaunchDaemons/`（需 sudo） |

常用参数：`--host` `--port` `--data-dir` `--env-file` `--node` `--run-user`
`--dry-run`（只打印渲染后的 unit/plist，不落盘）`-y`（不交互确认）。

**环境变量怎么进去。** 本项目不读 `.env`，所以由服务管理器把变量送进进程环境。
安装时会生成一个环境变量文件（用户模式 `~/.config/still-gallery/still-gallery.env`，
系统模式 `/etc/still-gallery/still-gallery.env`），里面放 `ARK_API_KEY`、`HOST`、
`PORT`、`DATA_DIR` 等。**优先级：环境变量文件 > unit/plist 里的兜底值**——
安装时写入的 `PORT` 只是兜底，改端口请改环境变量文件再 `restart`。
该文件权限是 `600`（里面有 API Key）。

**停止是干净的。** `server.mjs` 处理 `SIGTERM`/`SIGINT`：先 `close()` 停止接收新连接，
再 `flush()` 排空指标写盘队列，然后**以 0 退出**。两个管理器的重启策略都是
「**仅异常退出才重启**」（`Restart=on-failure` / `KeepAlive.SuccessfulExit=false`），
所以一次正常停止不会被立刻复活。重复发信号会强制退出（码 1）。

**日志**在 `<项目>/logs/`（`still-gallery.out.log` / `still-gallery.err.log`），
该目录已被 gitignore。

> **在 SSH / CI / agent 这类非 GUI 会话里，macOS 的 `launchctl bootstrap` 会失败**
> 并报 `Bootstrap failed: 5: Input/output error`——即使 `launchctl managername`
> 显示 `Aqua` 也一样（缺少会话的 mach 引导端口权限）。plist 已经写好了，
> **在 Terminal.app 里重跑一次同样的命令即可加载**，或直接重新登录让 `RunAtLoad` 生效。
> 这不是脚本问题，卸载/状态查询都不受影响。

### 生图凭据的两种来源

两个上游各有一份凭据，规则完全一致：

| 上游 | 环境变量 | 后台字段 | 接口 |
|---|---|---|---|
| 火山方舟 | `ARK_API_KEY` | API Key | `PUT /api/generate/config` 的 `apiKey` |
| 01ai 网关 | `IMAGE_RELAY_TOKEN` | 网关口令 | 同一个接口的 `relayToken` |

1. **环境变量** —— 优先级最高。此时后台界面里对应的输入框会被锁定，
   改动会返回 409 并提示「已通过 `XXX` 环境变量配置」。
2. **后台界面里填写** —— 保存到 `data/settings.json`（权限 `0600`）。

凭据**永远不会回传到浏览器**，前端只能拿到打码后的提示（`apiKeyHint` / `tokenHint`）。
所有生图请求都由服务端代理转发。

## 数据存储

`data/` 目录是**运行时状态**，全部已在 `.gitignore` 中排除。
`data/demo.json` 是唯一的例外——它是首次启动的种子数据，刻意保留跟踪。

| 文件 | 内容 | 权限 |
|---|---|---|
| `data/images.json` | 图片记录：地址、提示词、标签、来源、生成参数等。**原子写入**，每次写入前留一份 `.bak` | `644` |
| `data/images.json.bak` | 上一次写入前的快照 | `644` |
| `data/auth.json` | 管理密码的 `salt` + scrypt `hash` + `createdAt` | `644` |
| `data/settings.json` | 上游选择（`provider`）、方舟 API Key / 基础地址 / 默认模型、网关口令 / 地址、队列并发（`queueConcurrency`） | `600` |
| `data/metrics.json` | 生图耗时样本（每个请求一条，最多 2000 条）。同样是原子写入 + `.bak` | `644` |
| `data/generations.json` | 最近 24 小时的生成记录（索引；含提示词，过期即删） | `644` |
| `data/generations/` | 生成记录对应的图片文件，按需下载或内联落盘，24 小时后随记录一起删除 | — |
| `data/vault.json` | **后台图库**（私有）索引：标题、提示词、标签、来源、体积。原子写入 + `.bak` | `644` |
| `data/vault/` | 后台图库的图片文件，文件名由服务端生成（`<uuid>.<ext>`），**没有过期时间** | — |
| `data/clipboard.json` | **后台剪贴板**（私有）索引：文字原文、图片文件名与体积、创建时间。原子写入 + `.bak`，**只保留最近 100 条** | `644` |
| `data/clipboard/` | 剪贴板里的图片，文件名由服务端生成；随条目淘汰 / 删除一起删掉 | — |
| `data/uploads/` | 下载到本地的图片文件 | — |

> ⚠️ **不要把这些文件加回 git。** 一旦被跟踪，任何 `git restore` / `git checkout -- .` /
> `git clean` 都会静默回滚或删除真实数据，而症状看起来像是应用自身的 bug。

**关于登录会话：** 会话**不落盘**，存在服务进程内存里的一个 `Map`（以 token 的 SHA-256 为键，
24 小时过期）。Cookie 名为 `sg_session`，带 `HttpOnly; SameSite=Strict`。
**因此重启服务会让所有人重新登录**，这是预期行为。

## 生图（火山方舟 Seedream / 01ai 网关）

后台「AI 生成」标签页可以指向两个**协议完全不同**的上游，用页面顶部那条「上游」切换条选择。

| 上游 | `provider` | 协议 | 适合 |
|---|---|---|---|
| 火山方舟 Seedream | `ark` | `POST {base}/images/generations`，参数齐全 | 指定模型、尺寸、组图、联网搜索 |
| 01ai 网关 | `relay` | `POST {base}/v1/images`，**只有 4 个字段** | 只有网关口令，或想要固定画幅的快速出图 |

选择结果存在**服务端**（`data/settings.json` 的 `provider`），不是 `localStorage`——
真正决定这次请求打给谁的是服务端，界面只是它的投影；`PUT` 失败时界面会回滚。

两个上游是**两套独立的客户端**（`lib/image-gen.mjs` / `lib/relay-gen.mjs`）和**两个独立的注入点**
（`createApp({ generateImages })` / `createApp({ generateRelay })`），互不影响：
切到网关不会让方舟的模型能力矩阵失效，网关也不会被方舟的尺寸校验误挡。

### 方舟模式的三种生成方式

| 模式 | 说明 |
|---|---|
| 文生图 `text2image` | 只给提示词 |
| 文生组图 `text2group` | 一次生成多张（`sequential_image_generation: auto` + `max_images`） |
| 图生图 `image2image` | 带参考图；1 张传字符串，多张传数组 |

> 网关模式只有前两种，且**没有组图**——见下面「01ai 网关模式」。

### 按模型家族区分的限制（重要，仅方舟）

限制**因模型家族而异，不能一刀切**，规则只写在 `lib/image-gen.mjs` 一处，
前端通过 `/api/generate/config` 的 `modelCatalog` 取用（仅用于置灰和提示，不作数）。
下表按《Doubao-Seedream 5.0 文生图与图生图使用手册》校正过。

| 模型 | 参考图 | 组图 | 联网搜索 | fast | 透明背景 | 交互编辑 | 尺寸档位 |
|---|---|---|---|---|---|---|---|
| `doubao-seedream-4-0-20260415` | 2–14 | ✅ | ❌ | ✅ | ✅ | ✅ | `1K` / `2K` / `4K` |
| `doubao-seedream-4-5` | 2–14 | ✅ | ❌ | ❌ | ✅ | ✅ | `2K` / `4K` |
| `doubao-seedream-5-0-lite` | 2–14 | ✅ | ✅ | ❌ | ❌ | ❌ | `2K` / `3K` / `4K` |
| `doubao-seedream-5-0-flash-260915` | 2–10 | ❌ | ❌ | ❌ | ✅ | ✅ | `1K` / `1.5K` / `2K` |
| `doubao-seedream-5-0-pro` | 2–10 | ❌ | ❌ | ✅ | ✅ | ✅ | `1K` / `1.5K` / `2K` |
| `doubao-seedream-5-0-pro-260628` | 2–10 | ❌ | ❌ | ✅ | ✅ | ✅ | `1K` / `1.5K` / `2K` |

- 组图只有一条规则：**参考图数 + 生成数 ≤ 15**（5.0 pro / flash 上限为 1，即只能出单图）。
- 尺寸既可以填档位，也可以填 `宽x高`（如 `1024x1024`）。显式尺寸需满足：
  单边 512–4096、宽高比在 1/16–16 之间；**5.0 pro / flash** 额外要求总像素在
  **921600–4624220** 之间（`1280x720` 至 `2048x2048×1.1025`）。
- **`1.5K` 不是可有可无的第五档**：手册写明它与 `1K` 同价但效果更好，是最划算的一档；
  早先的版本漏了它，等于悄悄拿走了性价比最高的选项。
- 未收录的模型 ID 走**宽松默认值**（不挡死），由上游做最终裁判——
  挡掉一个我们只是没听说过的尺寸，比让上游报错更糟。
- 尺寸建议列表是**用同一个校验器过滤出来的**，所以建议值不可能与校验规则脱节。

> 4.0 / 4.5 的 `fast`、透明背景、交互编辑三列是**按宽松默认**给的：手册只覆盖 5.0 系列，
> 没有证据说 4.x 不支持，就不在本地拦。lite 的这三项是手册明确写了「—」的，所以关掉。

### 交互编辑：在参考图上框选

手册 4.4 的交互编辑用 prompt 里的定位标签指定区域，项目把它做成了可直接上手的工具：

1. 图生图 + 至少一张参考图 + 模型支持交互编辑时，提示词下面出现「在参考图上框选」；
2. 打开后是铺满屏幕的浮层，**拖动**画一个框 → 松开即插入 `<bbox>x1 y1 x2 y2</bbox>`；
   **轻点**（位移 < 10px）则插入 `<point>x y</point>`；
3. 标签插在提示词的光标位置，前面会自动补一个空格，不会和已有文字粘在一起。

坐标是**原图像素**，不是屏幕像素——浮层里图片是 `object-fit: contain` 居中的，
所以 `lib/ui.js` 的 `pointerToImagePixel` 先减去留白偏移再除以缩放比，否则框会整体偏掉。
这条换算有独立单测（`tests/ui-coords.test.mjs`），断言包括「反向拖拽也要归一化成左上角在前」。

移动端的几个必要处理：

- 画框层 `touch-action: none`，否则拖框会变成滚动页面；
- 浮层打开时给 `body` 加 `mark-open` 锁滚动，关闭时移除；
- 用 Pointer Events + `setPointerCapture`，鼠标 / 触摸 / 触控笔同一套代码；
- 图片元素撑满 stage（`width/height: 100%`），保证画框层和坐标换算用同一个矩形。

### 提示词字数守卫

手册给的建议是**中文 ≤ 300 字、英文 ≤ 600 词**，项目在提示词框下面实时显示：

```
中文 16 / 300 字 · 英文 5 / 600 词
```

超了只变琥珀色并加「（超出建议）」，**不拦提交**——手册写的是建议，上游并不会因为
301 个字就报错，本地拦下来只会把能成功的请求变成失败。计数逻辑是纯函数
（`public/ui.js` 的 `promptBudget`），中英混排时两个数分开算。
切到 01ai 网关时这一行改成网关自己的 `N / 4000 字` 硬上限。

### 提示词记录

输入框右侧是最近 **10 条**提交过的提示词，点一条就填回输入框（标题里有完整文本，卡片上
两行截断）。

| 项 | 规则 |
|---|---|
| 存哪 | 只存**这台浏览器的 `localStorage`**（`still-gallery:prompt-history`），不进 `data/settings.json`，也不进运行日志 |
| 容量 | 10 条，**先进先出**：新的一条放最前，超出从尾部裁掉 |
| 重复 | 同一条再提交不会堆十份，而是挪到最前——顺序和容量仍然是先进先出 |
| 何时记 | **入队成功才记**：400 / 429 被拒的提示词不该占掉一格 |
| 填入 | 当前输入框里的草稿如果**没提交过**（不在列表里），替换前先确认；已经在列表里的直接替换，不弹窗 |
| 清空 | 需确认，只清列表，不影响已生成的作品 |

为什么不存服务端：提示词是这台机器上的创作草稿，不是作品数据。多一份落盘就多一处会泄漏
提示词的地方——运行日志刻意不记提示词，就是为了同一个理由。代价是换浏览器或清站点数据
就没了，这是有意的取舍。

手机（≤760px）上列表改成输入框下面的**横向滑动**一条，竖排 10 条会把表单顶下去太远。

### 透明背景的三个前提

手册 4.5 的约束比「选个 transparent」复杂，缺一项上游只会回一句 `InvalidParameter`：

1. 模型必须是 **5.0 pro / flash**（lite 不支持透明通道）；
2. 必须是**图生图**，且**正好 1 张**参考图；
3. 输出格式不能是 `jpeg`（没有 alpha 通道）。

服务端按这三条逐项报错，前端在选中「透明」但条件不满足时也会先提示一次。
选项本身是**置灰**而不是隐藏：让用户知道「这个模型不支持」比让功能凭空消失更好。

### 结果预览（为什么不是直接把上游地址塞进 `<img>`）

上游返回的图片地址是**带签名的临时 URL**（TOS 对象存储，默认 24 小时有效）。
把它直接交给浏览器有两个问题：有效期一过就是 403 静默白框；而且它把浏览器的出网能力
当成了必需品。所以生成结果里同时给了两个地址：

| 字段 | 内容 |
|---|---|
| `url` | 上游的原始签名地址。用于「复制地址」和服务端导入，24 小时内有效 |
| `previewUrl` | **同源**句柄 `/api/generate/preview/<uuid>`。前端预览只用它 |

> 这一节讲的是方舟。网关返回的是内容寻址的**永久地址**，不存在过期问题，
> 但仍然走同一套预览句柄——前端不需要为两个上游写两套逻辑。

`previewUrl` 是服务端的一次性代理：**第一次被访问时服务端去下载一次并缓存**（120 条 / 96 MB
双上限，按 LRU 淘汰），之后重复查看命中缓存，不再打上游。因此预览不依赖浏览器能否访问 TOS。
下载失败会返回 502 并在卡片上显示可重试的提示，而不是留一个空白框。

> 未知 token 一律 404，所以这个接口不会变成开放代理。

**「导入图库」不再把地址回传给浏览器再回传回来。** 每个结果都带一个 `recordId`
（它同时也在「生成记录」里），前端优先 `POST /api/generations/:recordId/import`，
由服务端自己取原图。只有记录登记失败（拿不到 `recordId`）时才退回旧的
`POST /api/images { url }`。这不只是少一次往返：网关部署在本机时，原始地址是
`http://127.0.0.1:4399/...`，回传给 `/api/images` 会被 SSRF 规则当成内网地址拒掉
（400，0ms），而服务端那条路知道「这个地址是哪个网关给的」，能正常取图。

> 顺带：预览失败时前端只对 **https** 的原始地址做一次回退。本机网关的 `http://`
> 地址浏览器根本取不到，回退只会产生一串 404，看着像网关坏了。

**关于有效期解析：** 签名 URL 用 `X-Tos-Date`（签名时刻）+ `X-Tos-Expires`（**存活秒数**，
不是绝对时间戳）表示过期时间。这两者的解析只有一份实现，在 `lib/signed-url.mjs`，
由 `lib/image-gen.mjs` 和 `lib/log-parser.mjs` 共同引用——
历史上这里曾有两份不一致的副本，导致刚生成的图片被显示成「链接已过期」。

### 生成记录（最近 24 小时）

生成出来的图片**不会自动入库**——不入库的就只活在上游那张临时地址上，关掉页面就找不回来，
队列里的结果重启即失，内联（base64）返回的那种连预览都做不了。所以每次生成成功都会在
「生成记录」标签页留一条记录，保留 **24 小时**，期间可以回看、放大、补导入。

| 行为 | 说明 |
|---|---|
| 生成时 | 只写一条元数据（模型 / 尺寸 / 提示词 / 上游地址），**不下载** |
| 预览过之后 | 预览那一步下载的字节留在进程里，导入直接复用，**不再回源** |
| 没预览就查看 / 导入 | 服务端回源下载一次，落盘到 `data/generations/`，之后不再回源 |
| 内联（base64）结果 | 字节已在内存里，生成时直接落盘，因此也能查看和导入 |
| 到期 | 索引和图片文件一起删除，提示词也只保留这 24 小时 |

> 生成时不下载是有意的：生成路径已经在等上游出图，再串行下载 N 张会把「出图了没有」
> 的反馈推迟好几秒；而上游签名地址本身就有 24 小时有效期，按需拉取和它天然对齐。
> `tests/generation.test.mjs` 里有一条用例专门断言「生成阶段一次下载都不发生」。
>
> **预览缓存优先**同样是必须的，不是优化：预览和导入要的是同一批字节，回源两次就是
> 两次独立的网络依赖。网关前面挂着反代但 `/files/` 前缀没跟着转发、网关重启后端口变了、
> 或者那个地址只对某个 `Host` 头有效——只要第二次失败，用户看到的就是「图明明显示了，
> 却导不进来」。`tests/generations.test.mjs` 里那条用例让第二次下载必然抛错，
> 以此证明它压根没发生。

回源失败（签名地址已过期、上游 403）时，这张图会在列表里标成「原图链接已失效」，
而不是留一个永远转圈的灰图；再点一次仍会重试，避免一次网络抖动就把记录判死。
**具体原因也一起记在记录上**：卡片悬停能看到，点开放大后整条显示在图片下方——
「原图链接已失效」本身说明不了是端口被拒、上游 404 还是超时，而这三种的处置完全不同。

**导入**走的是和「AI 生成」面板完全相同的落库路径（`persistDownloaded`），
所以提示词关联、来源字段、图库筛选的行为都一致。同一张图重复导入会被 409 挡住——
除非那张图已经从图库里删掉了。

条数上限 400 条（`GENERATION_MAX`）。24 小时内正常用不到，它只是防止无人值守时把磁盘写满。

### 默认模型

「模型」输入框下面有一个 **默认模型** 快捷入口：显示当前默认值，并提供
「把当前模型设为默认」按钮（写入 `data/settings.json` 的 `defaultModel`）。
默认模型在两种情况下兜底：请求里没带 `model` 时，以及重新打开后台时「模型」框的初始值。

> 请求体的 `model` 会在**校验之前**就被解析成实际要调用的模型，因为尺寸规则是按家族区分的：
> 先按 `ARK_DEFAULT_MODEL` 校验、再拿配置里的默认模型去调用，会让 `4K` 通过本地检查后
> 撞上 Seedream 5.0 pro 的 400。

### 生图队列

「AI 生成」页的**「开始生成」直接把任务放进队列**，不再同步等待接口返回。
队列在 `lib/job-queue.mjs`，**同时最多跑 N 个任务**，N 可以在队列面板的「最大并发」里改
（默认 **8**，范围 1–32，存在 `data/settings.json` 的 `queueConcurrency`，重启后仍生效）。

为什么默认 8：控制台点一次生成就入队一次，串行会把六张图的等待叠成六倍；
而再往上加就该看上游账号的实际配额了——超了就是 429，并且为超时付费。

| 能力 | 说明 |
|---|---|
| 状态机 | `queued` → `running` → `done` / `failed` / `canceled` |
| 并发 | 1–32，默认 8。**调大立刻多起几个；调小只影响还没开始的任务**，在飞的请求已经计费，不会被打断 |
| 取消 | **只允许取消还没开始的任务**。`running` 的上游请求已经发出并计费，取消只会浪费掉这笔钱，所以接口返回 409 而不是假装成功 |
| 暂停 | 暂停只阻止新任务启动，正在跑的会跑完 |
| 移除 / 清除 | 只能操作已结束的任务；队列列表上限 60 条，超出的最旧记录自动淘汰 |
| 待处理上限 | 50 条（`queueMaxPending`），超过返回 429 |
| 结果 | 与直接生成完全同构：`url` + `previewUrl`，可在队列里预览并「导入图库」；**最后完成的那一批还会自动填进上方的结果面板** |

**提交后按钮立刻解锁**，所以可以连着点几次把多个任务堆进队列——`busy` 只覆盖「入队」这一次
请求，不覆盖任务本身。任务完成事件由队列轮询（2.5 秒）取回，前端记着「哪些是我提交的」
（`genState.watching`），结束时把那一批结果搬进结果面板。

**入库用的提示词是任务入队时冻结的那一份**（`label.prompt`），不是输入框的当前值——
和直接生成一样，否则排队期间改了提示词，存下来的关联就是错的。

**任务只存在内存里**，重启服务会清空队列。这不会造成费用损失：没开始的任务从未发出请求。
已下载的预览字节也在内存里，按**条数与总字节双上限**淘汰（120 条 / 96 MB，LRU）：
并发 8 的一轮组图就可能铸出 80 个预览令牌，上限太小会把先完成的那几张挤掉，
表现为图片 404、预览空白。只有「导入图库」才会落到 `data/uploads/`。

> 队列快照**永不回传 `referenceImages`**——图生图的参考图可能是单张 10MB 的 base64。
> 浏览器只拿得到 `label`（模型、模式、尺寸、参考图数量、提示词）。

### 生成指标

每一次真正打到生图接口的请求都会记一条耗时样本（`lib/metrics.mjs`），
**成功和失败都记**：失败的请求同样占用时间，只看成功会把平均拉好看，所以成功率与平均一起给出。
直接生成和排队生成记在同一个口径里，来源字段区分二者。

「生成指标」页展示：

- 顶部卡片：请求总数、平均出图时间、P95、每张平均、累计出图数；
- **按模型统计**：成功/请求数、成功率、平均 / 中位数 / P95 / 最快 / 最慢、出图数、每张平均，
  **按平均耗时从慢到快排序**——「哪个模型在拖后腿」是最常问的问题；
- **每张图耗时**：把请求级样本摊平成一行一张图；
- 最近请求：原始日志，含错误信息。

**计时口径（重要）：** 样本是**按请求**记的，不是按图片。组图请求
（`sequential_image_generation: auto`）上游只返回一个总耗时，响应里没有逐张耗时，
所以「每张平均」是 `总耗时 ÷ 张数` 的**估算值**，表格里明确标注「按张数分摊」；
单图请求的耗时就是那张图的耗时，标注「实测」。

样本上限 2000 条，写入 `data/metrics.json`（原子写 + `.bak`）。写入是**发射后不管**的：
磁盘慢不该让一次已经计费的生成返回失败。因此「响应回来了」不等于「文件已落盘」，
需要这个保证的调用方（测试清理数据目录、脚本读 `metrics.json`）应当先 `await app.flush()`。

### 01ai 网关模式（relay）

网关是另一套协议，请求体**只有四个字段**，其余参数它**静默忽略**（不报错、也不生效）：

| 字段 | 说明 |
|---|---|
| `mode` | **只接受 `image`**，别的值直接 `400 bad_mode`；文生图 / 图生图的区别不在这个字段 |
| `prompt` | 提示词，**上限 4000 字**（方舟是 8000） |
| `aspect` | 画幅，如 `4:3`；不传则由上游按 4:3 出图 |
| `image` | 参考图，**只能是 base64 data URL**，最多 1 张；带上它就是图生图 |

所以切到网关后，「模型 / 尺寸 / 优化模式 / 输出格式 / 背景 / 联网搜索 / 组图 / 水印」会**整块隐藏**，
而不是置灰——留一个能点却毫无作用的输入框是撒谎。`tests/relay.test.mjs` 里有一条用例
把 `model` / `size` / `seed` / `style` / `negativePrompt` / `width` 全塞进去，
断言它们**一个都不会出现在请求体里**，防止以后「顺手」加回去。

切换本身要落盘（`settings.provider`），所以前端 PUT 之后**核对服务端的回显**：
回显不是刚切的那个上游就当成失败回滚，而不是先弹一句「已切换」再把界面刷回原样。

> `mode` 这个字段名容易误导：它不是「文生图还是图生图」，而是网关的入口选择。
> 前端和指标里看到的 `text2image` / `image2image` 是我们自己的标签（`meta.mode`），
> 不出现在发给网关的请求体里。

**`aspect` 不做本地白名单。** 网关对未知画幅不报错，而是**静默回落到 4:3**。
界面只提供建议值，填别的也照发：

| 画幅 | 实际像素 |
|---|---|
| `1:1` | 1024×1024 |
| `4:3` | 1184×864 |
| `3:4` | 864×1184 |
| `16:9` | 1344×768 |
| `9:16` | 768×1344 |

> 边长会对齐到 32 的倍数，所以 `4:3` 实际是 1184×864，不是 1024×768。
> 这里刻意**没有**照方舟那套「本地校验」的写法：本地比上游更严的后果是
> 一个上游本来能跑的请求被我们挡下来，变成失败。

**切到网关后，界面是网关自己的一套，不是方舟那套减几个字段。** 提示词框上方的
「模型 / 尺寸」整行消失，换成画幅下拉 + 一条参数条，列的就是真正会生效的五项：

| 参数 | 取值来源 |
|---|---|
| 模型 | `config.relay.modelLabel`（固定 `mago-relay`，没有别的可选项） |
| 画幅 | `config.relay.aspects`，占位符是 `defaultAspect` |
| 提示词 | `config.relay.maxPromptChars`，同时写进 `maxlength` |
| 参考图 | `config.relay.maxReferenceImages`，超过的当场移除 |
| 出图 | 固定一次一张（组图那个标签页直接隐藏） |

方舟那句「参考图最多 14 张；尺寸支持 1K / 2K / 4K；不支持联网搜索」的模型说明在网关模式下
**必须收起来**——它是 `currentCapabilities()` 按模型算出来的，留着就等于在 01ai 界面上挂一条
Seedream 的参数，看着像没切换成功。参考图那行的提示文案（「可填 1–14 张」/「只能带 1 张」）
也跟着上游切换。

**参考图必须由服务端先下载再转 base64。** 网关不会替你下载图片，直接传 http(s) 链接
会得到 `502 upstream_error`。所以图生图时服务端复用已有的 SSRF 防护下载器
（`lib/downloader.mjs`）取回参考图再编码成 data URL；单张上限 11 MB，整体请求体上限 16 MB。
超过 1 张参考图时切上游会**当场移除多余的**并提示，而不是等到请求失败。

**网关返回的不是临时签名链接。** 它是内容寻址的永久地址（`expiresAt: null`），
所以预览和导入的行为与方舟一致，但不会 24 小时后失效。

#### 网关地址：本机优先

每次生成**先打 `http://127.0.0.1:4399`**（本机网关的默认端口），失败才退回配置里的域名地址。
候选链由 `resolveRelayEndpoints` 生成：`[本机, 配置地址]`，两者相同时只留一个。

「失败」的判据很窄，因为生图是付费操作：

| 情况 | 回退？ | 原因 |
|---|---|---|
| 连接失败（`ECONNREFUSED` / `ENOTFOUND` / `EAI_AGAIN` / `EHOSTUNREACH` / `ENETUNREACH` / 连接超时） | ✅ | 请求根本没发出去，不可能产生费用 |
| `404` / `405` | ✅ | 这个地址上没有网关路由，请求被别的东西接住了 |
| 读超时 / `AbortError` | ❌ | 说不清请求有没有到上游，可能已经出图计费 |
| 任何 `4xx` / `5xx`（400/401/403/429/500/502/503） | ❌ | 网关已经处理过这次请求，换地址重发就是再花一次钱 |

> **为什么必须认 404 / 405：** `4399` 是本机网关的默认端口，但它也可能被别的服务占住
> （或者网关只挂了一部分路由）。这种时候 POST 会被一个不认识 `/v1/images` 的服务接住，
> 回 `404` 或 `405 {"error":"不支持的请求方法"}`。只认连接错误的话，「本机端口被占」
> 就会变成一次必然失败的生图，而不是退回域名地址。

超时不会回退，所以「本机半死不活」不会变成一次双倍扣费；全部候选都连不上时，
报错会列出**依次尝试过的每个地址**和各自的失败原因。

关掉本机优先：`IMAGE_RELAY_LOCAL_BASE=off`（也接受 `none` / `0` / 空串），
此时请求只会打配置地址。

#### 网关的报错长什么样

网关有两种信封，`describeRelayFailure` 都认：

1. **ASP.NET 绑定错误**（`application/problem+json`）—— 参数类型 / 缺失问题。
   它**只报第一个**出问题的字段，顺序是 `mode` → `prompt` → `aspect`，所以要逐个改。
2. **语义错误**（`{"error":"code"}`）—— `bad_mode` / `empty_prompt` / `missing_token` /
   `invalid_token` / `upstream` / `upstream_error` / `rate_limited`。

其中 `upstream` 是**可以重试**的（连接阶段失败），`upstream_error` **不行**——
上游可能已经出图并计费。这条口径与方舟那边完全一致。

#### 网关的限制

- 每分钟 20 个请求，上游并发 2（排队超时 10 秒）；
- 提示词 ≤ 4000 字，请求体 ≤ 16 MB；
- 一次只出一张图，**不支持组图**——切到网关时「文生组图」标签会隐藏并禁用。

### 未实现的能力

`layer_decomposition`（图层拆分）**刻意没有做**：它返回一张底图加最多 16 个带透明通道的
PNG 图层（带 `z_index` / `name` / `bounding_box`），需要配套的图层查看器才能用起来，
否则只能存一堆彼此不知道谁盖谁的 png。它还会**每次请求预扣 17 IPM**、任一图层失败就整体失败，
属于「接进来容易、用起来难」的能力。能力矩阵里 `supportsLayerDecomposition` 已经就位，
以后要做时前端按它开关即可。

网关侧的**组图**也没有做——不是没来得及，是网关的协议里就没有这个参数，
一次请求只出一张图。

## 后台图库（私有）

后台的「后台图库」标签页是一个**只对已登录管理员可见**的图片库：里面的东西不会出现在首页画廊，
也不会出现在 `/api/images` 的返回里。两个入口：

| 入口 | 说明 |
|---|---|
| 上传本地图片 | 拖进虚线框，或点「选择文件」；一次最多 8 张，逐张上传并显示每张的结果 |
| 从生成记录导入 | 展开「从生成记录导入」，点选 24 小时内的生成结果，再点「导入选中」 |

### 为什么和公开图库分成两套存储

公开图库是 `data/images.json` + `data/uploads/`，每一张都会上首页。如果给同一条记录加一个
`visibility` 字段，那么**任何一次过滤写漏**都会让私有图片直接出现在公网上——而这个错误的
发现方式是「有人看到了」。所以这里用两个文件、两个目录、两条 API 前缀：

- 公开：`/api/images`、`/uploads/*`（静态文件，免鉴权）
- 私有：`/api/vault/*`（全部要求登录），原图走 `/api/vault/:id/file`

`tests/vault.test.mjs` 有一条用例专门断言「上传到后台图库之后，`/api/images` 仍然是空的」。

### 校验：只信字节，不信文件名

| 检查 | 做法 |
|---|---|
| 类型 | 服务端读魔数（PNG / JPEG / GIF / WebP / AVIF）；`Content-Type` 只是客户端的一句话 |
| 文件名 | 只用来**生成标题**；磁盘名一律 `<uuid><ext>`，扩展名同样由魔数决定 |
| 单张体积 | 15MB（和下载器共用 `MAX_IMAGE_BYTES`，不另立一份常量） |
| 请求体积 | 48MB；一次最多 8 张 |
| 总量配额 | 5000 张 / 4GB，超了**拒绝新增**而不是悄悄删旧的 |
| 路径 | 只按 id 拼 `data/vault/` 下的路径，不接受任何客户端路径片段 |

一张 `.exe` 改名成 `.png` 会带着 `image/png` 提交，但会在魔数这一关被拒——
`tests/vault.test.mjs` 用一段 shell 脚本字节验证了这条。

### 部分失败不回滚

一次传 5 张、坏了 1 张，另外 4 张没有理由一起作废。响应里 `added` / `failed` 分开返回，
前端逐条显示（`已入库 · 7.1 MB` / `不是可识别的图片…`）。前端也是**一张一个请求**：
单张失败不会连累同批，服务端也不必把几十 MB 同时读进内存。

### 从生成记录导入

走的是和「导入公开图库」同一条字节通道（`generationBytes`）：预览缓存命中就直接用，
没命中才用受信源站回源。所以「网关回传本机地址」那类问题不需要在这里再修一次。
导入后记录里保留 `source: 'generation'` 与 `sourceId`，卡片上标「来自生成」。

### 批量下载（勾选 → 打包成 zip）

批量条上的「全选本页」三态（全选 / 部分 / 未选）配合每张卡片左上角的勾选框，选中后
「下载选中」把 N 张打成一个 zip 一次下载。

**为什么是服务端打包，不是前端逐个 `<a download>`：** 同一个用户手势里连开多个下载，
浏览器通常只放行第一个，用户会以为丢图了。打包还有个副作用好处——包内文件名是
`01-标题.png`，解压出来就是可读的，而不是一堆 uuid。

| 决定 | 原因 |
|---|---|
| **不压缩**（store 模式） | PNG / JPEG 本来就压过，deflate 只能省 0–2%；而且 `deflateRawSync` 会同步阻塞事件循环 |
| **流式写 + data descriptor** | 单张 15MB、上限 200 张，攒成一个大 Buffer 峰值能到 GB 级 |
| **文件名剥路径 + 加序号** | 标题是用户输入的，可能带 `/`、`..`、控制字符；同名两张解压会互相覆盖 |
| **文件中途消失就跳过** | 少一张，不该让另外几十张一起失败 |
| **头发出后失败只能断开** | 响应已经是 `application/zip` 了，没法再换成 JSON；所以所有拒绝条件都在写头之前判完 |

包内文件名走 UTF-8 标志位（bit 11），中文标题在 macOS 归档工具、Windows 资源管理器、
`unzip`、Python `zipfile` 里都能正确显示。`tests/vault.test.mjs` 里有一个只够读回自己
产物的 ZIP 读取器，逐条校验中央目录、本地头与 CRC。

### multipart 是自己写的
项目零依赖，没有 `busboy` 可用，而 `<input type="file">` 是唯一不需要用户先把图片传到别处的
上传方式。`lib/multipart.mjs` 只做这一件事，并且**全程按 Buffer 切**：先 `toString()` 再按行切
会把图片里的 `0x0d 0x0a` 改成 U+FFFD，那是一次静默的数据损坏。用例里塞了含 CRLF 的二进制
正文来钉住这条。

## 后台剪贴板（私有，先进先出）

后台的「剪贴板」标签页记录**最近 100 条图文内容**：文字按 Markdown 原样保存，也可以带上图片。
它和后台图库同级（都要登录、都不上首页），但语义相反——图库是长期资产，**满了拒绝新增**；
剪贴板是流水，**满了挤掉最旧的**。

| 能力 | 做法 |
|---|---|
| 记录 100 条 | 条数上限在存储层，超出后从最旧的一条开始移出（连同图片文件） |
| 图文混排 | 一条可以是纯文字、纯图片、或两者都有；单条最多 8 张图，单张 15MB |
| Markdown | 存的是**原文**；界面渲染出来看，复制时可以选「渲染后」还是「纯文本」 |
| 关键词检索 | 服务端在文字里做子串匹配，不区分大小写 |
| 一键粘贴 | 面板上任意位置 Ctrl/⌘+V，图片直接变成待保存附件（拖文件进来同理）；也可以在编辑区里粘 |
| 一键复制 | 默认写「渲染后的样子」；复制按钮旁的 ▾ 里还有 仅文本 / Markdown 源码 / 图片 |
| 本地持久化 | `data/clipboard.json` + `data/clipboard/`，重启后还在 |

### 为什么存服务端，而不是 localStorage

提示词记录（最近 10 条）刻意放在 `localStorage`，因为那是这台浏览器上的草稿。剪贴板不一样：
**图片塞不进 localStorage**（配额 5MB，两张截图就满），而且换台设备就没了。这里的「本地」
指的是「落在自己的 `data/` 目录里」——和后台图库、生成记录一致。

代价要说清楚：剪贴板会记下你复制的一切，**包括密码和令牌**。所以它和后台图库一样要登录，
并且 `/api/clipboard/*` 一律 `requireAuth`；运行日志里**只记条数和字数，绝不记内容**
（`tests/clipboard.test.mjs` 有一条用例专门往剪贴板里存一个 `sk-` 开头的假令牌，然后断言日志里
找不到它）。

### 先进先出：淘汰是需求，不是偷懒

| 上限 | 值 | 触发时 |
|---|---|---|
| 条数 | 100 | 移出最旧的一条 |
| 单条文字 | 100000 字符 | 拒收（400），不截断——截断会悄悄毁掉一篇文档 |
| 单条图片 | 8 张 | 拒收（400），并说明上限 |
| 总字节 | 256MB | 从最旧的开始移出，**但永远留住刚写进来的那条** |

淘汰会在响应里报数（`{ evicted: n }`），前端提示「最早的 N 条已移出」。
静默丢数据比丢数据本身更让人恼火——用户至少该知道刚才那一下挤掉了什么。

上限虽然由服务端判定，字数却摆在编辑框下面（`20,000 / 100,000 字`），超了变红：两万字贴进去，
人第一反应是「是不是超长了」，让他点了保存才收到 400 是最差的答案。同理，如果服务端进程还是
旧代码、`/api/clipboard` 根本没注册，界面会把兜底的「接口不存在」翻成「服务端还在跑旧代码，
没有剪贴板接口——重启服务后再试」，而不是让用户去数自己贴了多少字。

淘汰顺序是「先写索引，再删文件」。反过来的话，索引写失败就会留下一堆指向空文件的记录，
列表里是一排永远加载失败的缩略图。

### 同一条内容不会占两个位置

和**最新一条**完全相同时（文字一致、图片的 sha256 逐个一致），不新增记录，只把它提到最前并
更新时间，响应里 `deduped: true`。否则「复制 → 粘贴 → 再保存」会很快把 100 格填满。

### Markdown 是自己写的渲染器

项目零依赖、没有打包步骤、CSP 是 `script-src 'self'`，CDN 上的 marked / markdown-it 一个都
加载不了。`public/markdown.js` 支持标题、围栏代码块、引用、列表、分隔线、行内代码、粗体、
斜体、删除线、链接——**不支持**表格、图片、嵌套列表：前两个要么需要另一条渲染管线，要么会
引入外部请求（远程图片就是追踪像素），真要看原文，卡片上有「源码」开关。

安全上只有一条规矩：**先转义，再上标签**。用户贴进来的任何字节先过 `escapeHtml`，之后所有
`<` 都已经是 `&lt;`，插入的标签都是自己拼的常量；链接另有一道白名单（只放 http / https /
mailto / tel / 相对路径），`javascript:` 与 `data:` 按纯文本渲染。

`tests/markdown.test.mjs` 里一半是安全用例——这个后台的会话能删图、能花钱生图，一处漏转义
就是存储型 XSS。

### 复制：默认给的是「渲染后的样子」

系统剪贴板是个**多格式容器**，同一份内容可以同时放几种格式，粘到哪儿由**目标**挑它认识的
最好的那份。所以「复制」写的是两份：

| 格式 | 内容 | 谁会用它 |
|---|---|---|
| `text/html` | 渲染后的 HTML，带行内样式 | Word、公众号编辑器、Notion —— 标题、列表、粗体都在 |
| `text/plain` | 去掉 Markdown 标记的纯文本 | 输入框、终端、微信 —— 不会出现一屏 `**` |

只写一种都不行：只写 HTML 的话，粘到记事本里是一堆标签；只写纯文本的话，粘到文档里
格式全丢。「仅复制文本」是把这个选择权交给用户（只要 `text/plain` 那一份）。

三个细节：

- **行内样式而不是 class**：粘贴目标不加载我们的 `styles.css`，`<pre>` 会退化成一行挤在
  一起的等宽字。`CLIPBOARD_STYLE` 里只给 `pre` / `code` / `blockquote` / `hr` / `a` 加了
  样式——标题和列表交给目标自己排，那才是它该有的样子。
- **图片内联成 data URL**：`/api/clipboard/:id/file/0` 是**要登录**的私有地址，贴到别处
  只会得到一张 401 的破图。剪贴板里的东西必须自包含。
- **纯文本化保留行结构**：段落、列表、代码块的行都在，只去掉标记。无序列表的 `-` 换成
  `·`，有序列表的 `1.` 保留——序号是内容，不是标记。全压成一行那是摘要，不是复制。

### 一键粘贴为什么是「尽力而为」

| 通道 | 能拿到什么 | 失败时 |
|---|---|---|
| `navigator.clipboard.readText()` | 文字 | 忽略，继续试下一条通道 |
| `navigator.clipboard.read()` | 图片（多数浏览器要额外授权） | 忽略 |

两条都拿不到就提示「请直接按 Ctrl/⌘+V」。**不能**因为读不到剪贴板就让按钮报错——用户手里
明明有内容，只是浏览器不给，这时候告诉他下一步怎么做才有用。

「一键粘贴」只是入口之一：面板上**任意位置**按 Ctrl/⌘+V 都行（`paste` 监听挂在整块面板上），
图片会直接变成待保存的附件。截图粘进来时浏览器把它当成「一个文件」，默认行为要么什么都不做，
要么把文件名插成一行文字，所以带文件时一律拦下默认行为；纯文本部分手动插到光标处——从
Word / 网页复制的「图 + 说明文字」就是这条路。

唯一不碰的地方是**卡片里的编辑框**：那是在改一条已有记录，浏览器原生粘贴（光标位置、撤销栈）
比我们可靠。

### 图片同样只信字节

`sniffImage` 认魔数，认不出就**整条拒绝**。这里和后台图库刻意不同：图库里每张是独立作品，
坏一张、好的照进；而一条剪贴板是一个整体，缺一张就变成残的，不如直接告诉用户是哪一张有问题。

## 日志导入 CLI

把 `whiteboard_agent.log` 解析成画廊的记录结构，并可选择直接导入。
解析逻辑在 `lib/log-parser.mjs`（纯函数，有独立单测），CLI 只是它的外壳。

```bash
# 只看解析结果（表格）
node scripts/parse-log.mjs ~/Downloads/whiteboard_agent.log

# 输出完整 JSON 以便检查 / 管道处理
node scripts/parse-log.mjs whiteboard_agent.log --json --out /tmp/parsed.json

# 导入到正在运行的服务（图片由服务端下载）
node scripts/parse-log.mjs whiteboard_agent.log --import --password '<管理密码>'

# 直接写数据目录（不经过 HTTP，需要先停掉服务）
node scripts/parse-log.mjs whiteboard_agent.log --local --data-dir ./data
```

| 选项 | 说明 |
|---|---|
| `--out <path>` | 把解析结果写成 JSON 文件 |
| `--json` | 打印完整 JSON 而不是表格 |
| `--import` | 通过画廊 HTTP API 导入 |
| `--local` | 直接写数据目录（不经过 HTTP） |
| `--data-dir <path>` | `--local` 用的数据目录，默认 `./data` |
| `--server <url>` | 画廊地址，默认 `http://127.0.0.1:4317` |
| `--password <pw>` | 管理密码，也可用 `GALLERY_PASSWORD` |
| `--tags a,b,c` | 给每个导入项附加的标签 |
| `--limit <n>` | 只处理前 n 个 session |
| `--include-empty` | 也列出没产出图片的 session（永远不会被导入） |

> 日志里有多个字段是被**截断**的，解析时会优先取完整来源，细节见 `lib/log-parser.mjs`。

## 运行日志

后台的「运行日志」标签页看的是**服务进程自己的事件**，和上面的「日志导入」不是一回事：
后者是把 `whiteboard_agent.log` 里的历史会话导进画廊，前者是「刚才这个进程做了什么」。

记什么：

| 事件 | 级别 | 说明 |
|---|---|---|
| `POST/PUT/DELETE /api/*` | `info` | 所有写操作，带状态码与耗时 |
| 失败的 `GET`（4xx） | `warn` | 鉴权失败、参数不合法 |
| 5xx | `error` | 含未捕获异常 |
| 生图成功 / 失败 | `info` / `error` | 上游、模型、模式、耗时、失败原因 |

**失败的那一行会带上原因**，跟在耗时后面：

```
error http POST /api/generations/9f8b35e5…/import → 502（12043ms）：原图已经取不回来了：图片地址返回 404
```

这不是锦上添花。线上前面通常挂着 CDN，**5xx 的响应体会被换成一张通用错误页**，
前端 `api()` 只能拿到「请求失败（502）」，真正的原因在浏览器里根本看不到。
日志是唯一一定到得了运维眼前的通道。401 不带原因（没登录没有信息量，
而且会把「哪些路径存在」写进日志），其余原因压成一行并截到 160 字符。

**成功的 GET 不记**（画廊和队列都在轮询，会把面板刷满），`/api/logs` 自己也不记
（面板轮询自己会自我放大）。

三条设计约束：

1. **只存在内存里**，容量 800 条，进程重启即清空。没有落盘、没有轮转、没有保留策略——
   也就不会在磁盘上攒出一份包含提示词的历史。要看历史请用 `journalctl` / launchd 的 stdout。
2. **有界**：单条 message 截到 2000 字符，scope 截到 40；内存占用可推算。
3. **不抛错**：未知级别退化成 `info`，日志本身不该成为故障点。

`GET /api/logs?level=warn&limit=200` 返回 `{ entries, size, limit, dropped, total }`，
`entries` 是**最新在前**，`level` 是**下限**（`warn` 表示 warn + error）。
`DELETE /api/logs` 清空，并留下一条「清空了 N 条」的记录。

面板默认级别是 **`info` 以上**，不是 `warn`：一个健康的服务本来就不产生警告，默认按 `warn`
过滤会让人点进「运行日志」只看到一句「暂时没有符合条件的事件」，读起来就像这个标签页坏了。
拉取失败时面板里会留一行「日志加载失败：…」，而不是把空列表和请求挂了显示成同一个样子。

### 编码完整性守卫

`tests/encoding.test.mjs` 会扫描全部源文件，检查两类损坏：

1. 是否含 U+FFFD 替换字符；
2. 是否存在「三字节 UTF-8 序列的第三个字节被替换成 `?`（0x3F）」的字节特征
   （例如 `确` = `e7 a1 ae` 被写坏成 `e7 a1 3f`）。

这个守卫是必要的：**本项目历史上两次把中文文案写坏过**，损坏后的界面文案会显示成
「单次最多处」后面跟一个替换字符（U+FFFD）和一个问号，再接「200 张图片」这种样子。该测试内含自检，会验证扫描器确实能抓到真实损坏字节。

**改动含中文的文件后，请务必跑一次测试。**

## 安全设计

- **SSRF 三层防护**（图片下载）：URL 白名单 → DNS 解析后校验**全部**返回地址 →
  把校验过的 IP 钉进 socket（防 DNS rebinding）。最多 3 次重定向，请求超时 15 秒。
- **唯一例外是「操作者自己配置的网关」**：网关部署在本机或内网时，它返回的
  `http://127.0.0.1:4399/files/x.png` 在通用规则下会被当成攻击拦掉（端口不在
  白名单、地址是保留段），表现为「生成成功，但预览 502、导入 400」，而且都是
  0–1ms 就失败——因为一个字节都没发出去。所以生成时会记下**真正回了话的那个
  源站**，取图时只把这一个源站放进白名单：
  - 白名单只由服务端从「哪次生成、哪个 endpoint 答的」推导，**永不从请求里读**；
  - **每一跳重定向重新判定**，跳到别的源站立刻退回完整校验；
  - 协议、禁止携带凭据、体积上限、魔数校验一条不少；
  - 客户端直接 `POST /api/images` 的地址**没有**这个例外，内网地址照旧拒绝。
  - **老记录还有一层兜底**：`sourceOrigin` 是随这个修复才写进索引的，之前登记的
    记录没有这个字段。所以白名单里还会加上**配置里声明的网关源站**
    （`IMAGE_RELAY_BASE` 与 `IMAGE_RELAY_LOCAL_BASE` 的 origin）。这些值来自运维
    自己的配置，不是请求带来的；把本机网关关掉（`=off`），这条兜底也跟着关。
- **网关返回本机地址时先改写**：`parseRelayResponse` 认出 loopback / 保留段
  地址后，换成回了话的那个源站（有 `id` 用 `/files/<id>.png`，没有 `id` 就保留
  原路径），所以远程网关把说明书里的 `127.0.0.1:4399` 示例原样吐回来时也能取到图。
- **格式以魔数为准**，不信任 `Content-Type`；单张图片上限 **15 MB**。
- **认证**：单管理员账户，scrypt 加盐哈希，比较用 `timingSafeEqual`；
  会话 Cookie `HttpOnly; SameSite=Strict`；所有写操作额外校验同源。
- **会话过期由前端统一收口**：`ui.js` 的 `api()` 遇到 401 会抛一个 `sg:unauthorized`
  事件，后台收到就退回登录页并说明原因。各面板自己处理 401 只会变成一堆「加载失败」，
  人却还停在控制台上，点哪儿都像没反应——会话存在进程内存里，**重启服务就会过期**，
  这在实际使用中并不罕见。
- **密钥不外泄**：`ARK_API_KEY` 永不硬编码、永不回传浏览器、永不写入日志；
  只从环境变量或 `data/settings.json`（`0600`）读取。
- **CSP 是严格的 `script-src 'self'`**，没有 `unsafe-inline`、没有 `unsafe-eval`。
  页面本身只用外链模块脚本，所以不受影响；但**前置 Cloudflare 时控制台会报两条被拦截的脚本**：
  一条是 CF 注入的 `<script>`（`__CF$cv$params` + `/cdn-cgi/challenge-platform/...`），
  一条是 `static.cloudflareinsights.com/beacon.min.js`。两条都是 CF 自己的遥测/机器人检测，
  **不影响应用功能**。想彻底消掉就在 CF 后台关掉该域名的 Web Analytics 与 Bot Fight Mode，
  不要为此给 CSP 加 `unsafe-inline`。
- **运行日志不含密钥**：只记方法、路径、状态码、耗时与错误文案；请求体和响应体都不进日志。
- **请求体上限**：普通接口 64 KB；`POST /api/generate` 因为要内联 base64 参考图，
  单独放宽到 48 MB，且该路由同时受 Cookie、同源校验和限流三重约束。
- **后台图库是私有的，靠「存储隔离」而不是「查询时过滤」**：它有自己的索引
  （`data/vault.json`）、自己的目录（`data/vault/`）、自己的 API 前缀（`/api/vault/*`），
  所以公开的 `/api/images` 与 `/uploads/*` 从结构上就取不到它——不存在「过滤条件写漏」这种
  失败模式。原图端点 `/api/vault/:id/file` 走 `requireAuth`，和公开静态目录完全分开。
  上传只信魔数、文件名只用于生成标题、磁盘名一律服务端生成，配额满了**拒绝新增**而不是
  删旧的。
- **参考图**：单张上限 10 MB，地址长度上限 2048 字符，最多 14 张。

## 已知限制与注意事项

- **单进程、单管理员**。会话在内存里，没有多用户、没有角色、没有审计日志。
- **改了文件必须重启进程**，静态资源一律 `no-cache` + ETag（每次回来问一句，没变就 304）。
  资源名里没有内容指纹，所以**不能**给长缓存：HTML 是 `no-store` 而 `admin.js` / `styles.css`
  缓存 4 小时的话，发布后会变成「新 HTML + 旧 JS/CSS」，症状是**按钮点了没反应、布局错位、
  下拉箭头不见了**，而且刷新也不一定好（浏览器和 CDN 各有一层缓存）。
  进程没重启时它仍在用旧代码发旧的 `Cache-Control`，所以「同步了文件」不等于「部署完成」。
  若前面挂了 Cloudflare，发布后顺手清一次缓存（或确认它尊重 `no-cache`）。
- **资源引用带版本号**：HTML 里的 `/styles.css`、`/admin.js` 与 JS 的相对 import 会被服务端
  改写成 `?v=<内容指纹>`。这是给「前置代理不听话」兜底——nginx 的 `expires 4h` 或 Cloudflare
  的「浏览器缓存 TTL」会**覆盖**我们发的 `no-cache`（判据：响应头里出现两个 `Cache-Control`，
  或者静态资源是 `max-age=14400` 而代码里写的是 `no-cache`）。URL 变了，代理只能换 key 缓存。
- **服务本身不提供 HTTPS**，默认只监听 `127.0.0.1`。要对外暴露请自行加反向代理。
- **生图会真实计费**。`POST /api/generate` 直接打到上游并消耗额度，
  日常回归不要拿它做冒烟测试；测试套件用的是打桩实现，不会产生费用。
- **生图结果不落盘。** 预览句柄和已下载的预览字节都只存在**进程内存**里
  （120 条 / 96 MB 双上限，按 LRU 淘汰），重启服务后旧句柄全部失效，只能重新生成（会重新计费）。
  要长期保存请用卡片上的「导入图库」——那一步才会把图片下载进 `data/uploads/`。
- **控制台走队列，但 `POST /api/generate` 仍然存在。** 那个接口是同步执行、**不受队列并发数约束**的，
  留给脚本和排障用；日常点「开始生成」走的是 `POST /api/generate/queue`。
- **生图队列也不落盘。** 重启服务会清空队列；未开始的任务不会产生费用。
  队列没有重试：失败的任务会保留错误信息供排查，要重跑就重新提交一次。
- **「每张平均」是估算值。** 组图请求上游只给一个总耗时，响应里没有逐张耗时，
  所以按张数摊算；表格里标注「按张数分摊」以示区分，单图请求标注「实测」。
- **耗时样本最多 2000 条**（`data/metrics.json`），超出后最旧的被淘汰；
  清空历史只删统计数据，不影响已入库作品。
- **两个上游的额度是分开的**，切换不会迁移任何东西。队列里已排队的任务会**保留入队时的上游**
  （`label.provider`），不会因为中途切了上游就悄悄改成扣另一个账号的钱。
- **网关模式下每次生成都会先探一次本机地址**。代价是一次 loopback 连接（端口没开时是
  `ECONNREFUSED`，微秒级），换来的是本机网关起来后立刻生效、不需要重启。本机地址若返回
  **200 但不是 JSON**，会直接报「网关返回的不是合法 JSON」而**不回退**——200 意味着那个地址
  真的处理了请求，此时重发可能造成二次计费。
- **`data/` 是真实数据，不是缓存。** 清理它等于删库。
- 画廊里的 `aspectRatio` 字段历史值其实是**尺寸参数**（`"2K"` / `"1664x2496"` / `"4:3"`），
  不是宽高比。前端会按正则解析并回落到 1，再在图片 `load` 后用真实比例自愈。
- 部分历史记录的 `title` 字段里装的是**整段提示词**（因为导入时没有单独的标题）。
  主界面的浮层标题因此限制为 2 行，完整内容在详情页展示。

## 视觉风格（低多边形）

界面是一套**平面着色**的几何材质，不是软凹凸（neumorphism）：每块面板由 2–3 块
平面拼成，平面之间是**硬色标**（没有过渡），板的下沿有一条实心厚度边。立体感来自
「板浮在台面上」，而不是「面被按进纸里」。

### 三层材料

| 令牌 | 是什么 | 用在哪 |
| --- | --- | --- |
| `--face` | 凸起的面：三块平面 + 一条 114° 折线 | 顶栏、工具栏、面板、按钮、卡片 |
| `--face-soft` | 只有两块的浅折面 | 胶囊、激活的标签 |
| `--well` | 凹槽：两块更暗的平面 | 输入框、预览框、标签栏、代码块 |
| `--accent-face` | 主色折面（三块靛蓝） | 主按钮 |
| `--tint-ok` / `--tint-danger` / `--tint-warn` | 语义底色 | 成功 / 失败 / 警告条 |

> **为什么折线是 114° 而不是 160°**：160° 的渐变几乎垂直，切出来的是水平色带，
> 读起来像「渐变」；斜着穿过面板才会读成「折面」。同一个理由，凹槽用 `164deg`
> ——往下沉的面不该有发散感，只要一条折线。

### 底纹是一张真的三角网格

`public/lowpoly-mesh.svg` 是 8×8 网格三角化后的 128 个平面着色三角形（960×960
可平铺）。**只有内部顶点会被抖动**，四条边保持规则间距，所以任何一块都能和邻块
严丝合缝。

用 SVG 而不是 CSS 渐变：两块色标的渐变最多只能做出一个折痕，而低多边形的「面」
是大量平面在硬边上交汇。整张图约 12 KB，没有滤镜和模糊，绘制成本比多层
`background-image` 更低。

改网格参数（格数、抖动幅度、色板）后重新生成，输出是确定性的，可逐字节复现：

```bash
node tools/gen-mesh.mjs public/lowpoly-mesh.svg
```

### 切角与「厚度」

```css
clip-path: polygon(var(--cut) 0, 100% 0,
                   100% calc(100% - var(--cut)), calc(100% - var(--cut)) 100%,
                   0 100%, 0 var(--cut));
```

- **只切左上、右下两刀**。四角全切会读成圆角矩形，两刀才留下方向感。
- 切角会**把 `box-shadow` 一起裁掉**，所以这几个壳体的外投影改用
  `filter: drop-shadow()`——它跟着多边形走；板的厚度由内侧 `inset` 暗边补回来。
- `--cut` 在 760px 以下收成 12px：窄屏内边距只有 18px，18px 的切角会啃到内容角。

**瀑布流卡片不切角。** 照片是内容不是装饰，切角会切掉它自己的边；卡片只收圆角到
3px 并压一条实心暗边，几何感交给背景和外壳。

### 改风格只改 `:root`

所有材质都定义在 `:root` 的 20 多个令牌里（`--facet-*`、`--face*`、`--well`、
`--raise-*`、`--press-*`、`--cut`、`--radius*`）。调色只改 `--facet-*` 四档明度，
换「折」的方向只改 `--face` 的角度。样式表里剩下的 `var(--face)` 不用动。

## 人工验证 UI

`tools/shot.mjs` 用 CDP 驱动无头 Chromium 截图，不需要安装 Playwright/Puppeteer
（会去 Playwright 的浏览器缓存里找已下载的 Chromium）：

```bash
node tools/shot.mjs --url http://127.0.0.1:4317/ --out /tmp/gallery.png

# 带登录 Cookie、并执行一串有序的交互步骤
node tools/shot.mjs --url http://127.0.0.1:4317/admin --out /tmp/admin.png \
  --cookie "sg_session=<token>" \
  --click "#tab-generate" --script "document.title" --settle 2000
```

支持 `--file "#input=path"`（设置文件输入）、`--click "#sel"`（点击）、
`--drag "x1,y1,x2,y2"`（真实鼠标拖拽）、`--script "js"`（求值，支持 await），
按命令行给出的顺序依次执行。

> `--drag` 走的是 CDP 的输入域，不是合成 `PointerEvent`——后者被 `setPointerCapture`
> 拒绝，且没有移动过程，凡是带「拖动阈值」的交互（比如在参考图上框选）都测不出来。

> 每个 `--script` 都是**同一个全局词法环境**里的一次求值，两次都用 `const x = …` 会抛
> 「Identifier 'x' has already been declared」。需要局部变量时用 IIFE 包起来。

默认整页截图（`captureBeyondViewport`）。截图对象是**浮层 / 下拉菜单**时加 `--viewport-only`：
Chrome 在整页合成时会重排绘制层级，压在别的层上的绝对定位元素会把下面的文字透出来，
看起来像背景半透明——那是截图伪影，不是样式问题。

> 会话 Cookie 存活在服务进程内存里，**只能从仍然活着的进程签发**，
> 从旧日志里复制出来的 token 一定是失效的。
